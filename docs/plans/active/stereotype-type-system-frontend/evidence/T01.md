# T01 input-boundary evidence

## Observable boundary

`core.input` is delivered as bundled browser resources, activated as a Cordis
plugin, executed in an isolated Wasmoon state, and adapted to distinct editor
`success`, `error`, `unresolved`, and `fault` outcomes. The deprecated engine,
live graph, persistence, UI, and backend are unchanged.

The test-only candidate and oracle adapters exchange protocol-v1 JSON over
stdin/stdout in separate Bun processes. For the symbolic model, both returned:

```json
{"status":"success","output":{"shape":["B",3,32,32],"dtype":"float16"}}
```

For the omitted-dtype model, both returned:

```json
{"status":"success","output":{"shape":["batch",128],"dtype":"float32"}}
```

The candidate classifies a missing required `shape` as editor `unresolved`
before Lua. The pinned oracle currently returns an expected parameter error;
this deliberate difference follows the normative integration design.
