# T08 evidence — MCP diagnostics and exact package bundles

## Browser/MCP transport

`get_graph`, `get_type_info`, and `get_package_diagnostics` expose the
browser-owned `packageRuntimeReady` flag and `packageRuntimeDiagnostics` array.
The MCP `get_package_diagnostics` tool only calls that browser RPC and keeps no
catalog, diagnostic cache, IndexedDB access, local-directory access, or runtime
implementation. `list_stereotypes` forwards lifecycle metadata when supplied by
the browser-owned catalog state.

## External bundle example

The following is a manifest-only example of the fields emitted for an external
package; source bytes are intentionally omitted from this evidence:

```json
{
  "format": "package-bundle/v1",
  "package": {
    "id": "vendor.layer",
    "version": "2.0.0",
    "resolvedDependencies": { "core.input": "core.input@0.1.0" },
    "files": {
      "helpers/constants.bin": { "size": 4, "sha256": "<sha256>" },
      "lua/inference.lua": { "size": 21, "sha256": "<sha256>" },
      "manifest.json": { "size": 243, "sha256": "<sha256>" },
      "pytorch.py": { "size": 14, "sha256": "<sha256>" },
      "stereotype.json": { "size": 118, "sha256": "<sha256>" }
    }
  }
}
```

Resource selection is by exact `id@version`; dependency closure rejects missing,
inactive, wrong-version, ambiguous, or failed records. Installed resource maps
are exported byte-for-byte in deterministic path order, including helper files
and declared Python entrypoints. Existing bundled fixtures retain their
`package-bundle/v1` shape.
