# T06 evidence — runtime reconciliation and exact project references

## State transitions

`installed -> activating -> active` is keyed by exact `id@version`. A failed
activation records `failed` and is not retried by graph reconciliation; only an
explicit activation with `retry: true` retries it. Concurrent requests for the
same key share one in-flight promise. A context permits one active version per
ID and reports a conflict for a second version. Disposal marks active entries
disposed after waiting for in-flight work, then disposes the host.

## Project migration

`DiagramCore.parseProjectJson()` validates and canonicalizes a project off-state;
`commitProject()` is the sole graph commit path. Existing node identities with
`name` remain readable, but name is ignored for lookup and the exporter writes
only `{ id, version }`. Missing IDs or versions are rejected without mutation.
`Diagram.importProjectJson()` reconciles every exact reference before one commit.

## Removal

Only external records may be removed. Removal rejects bundled, active,
current-diagram-referenced, and installed-dependent packages, then deletes the
store record and rebuilds the composed catalog/runtime.
